# V2-minimal (implementation + mechanical tests) — 2026-10-21

User GO (2026-10-21): fresh multi-sampling + trusted contract gate; no repair, no distinguishing-input selector, no LAYA, no GLM critic, no training.
Built as a small isolated module; P5, V1.5, the frozen grading sets and the P5 results are unchanged (only new files; `tools/verify_p5_pins.py` 82/82).
Not evaluated: the next full evaluation (P6) needs fresh tasks and pre-registered equal actual-token budgets.

## Code
`evidence_ladder/v2min.py` (`VERSION = "v2min_v1"`):
- `sample_loop`: arm B's sampling path (round 1 = `GEN.plan_samples` seeds 1–4; fresh rounds of 2, seeds `100 + 2·round + j`, `GEN.strategy_for` templates,
  `max_new = min(4096, budget − used)`, same public-pass rule), with an optional per-candidate gate. With no gate it is call-for-call identical to
  `tools/el_p2_generation_compare.run_arm` (test 1), which is left untouched because it belongs to the frozen P5 bundle.
- `ContractGate`: the frozen V1.5 runtime check (contract edges + `l2.derive_inputs(public, 6)`, `contract_v1.evaluate`); authority only from the host registry
  or an allowlisted parser. Verdicts `pass` / `fail` / `unavailable`; a tool failure raises `ContractToolError` (infrastructure, never a verdict).
- `solve(policy, …)`:
  - `"b_veto"` — REFERENCE: B unchanged, then the contract vetoes B's selection (→ no answer).
  - `"gate"` — PROPOSED: every public-passing candidate is gated; a proven failure is rejected and sampling continues; the first candidate passing every
    applicable check is returned at once; budget exhausted → abstain.
  - Labels `SUPPORTED` / `BLOCKED` only; `checks.contract` says `pass` or `unavailable` (public-only acceptance). Never `VERIFIED`.

## Tests (`tools/test_v2min.py`, CPU only, scripted model, MXC + trusted verifier, qualification fixtures Q01–Q04): 10/10 pass
equivalence with arm B (two budgets; a round-size mutant is detected) · gate rejects a public-passing hard-code and continues to the correct program ·
stops right after acceptance (in round 1 and in a fresh round) · b_veto blocks B's hard-code · diagnostic-only contract → `unavailable`, public-only acceptance ·
allowlisted-parser contract rejects a crashing hard-code · budget exhausted → abstain · public failures never reach the gate · tool failure raises ·
no result labelled VERIFIED.

## Expected behaviour (not measured)
Where no authoritative contract exists (all of LiveCodeBench), `gate` behaves exactly like B. The per-candidate gate's benefit over `b_veto` (continuing
after a rejection) is unmeasured. V2-minimal is a simpler, reliability-oriented successor; it is not shown to solve more problems than B.
