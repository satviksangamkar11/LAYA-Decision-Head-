## 2. Dataset logic (my design; every choice justified)

### 2.1 What a training row is
A **decision point** = (state at step t of a trajectory, candidate next actions, NONE). The head reads Qwen's hidden states for the state (query) and for each option (span mean), so every row needs a Qwen forward over the rendered prefix and options (capture, frozen Qwen, same device class and dtype for TRAIN/CAL/test). Row fields: `decision_id, source, trajectory_id, instance_id, repo, step, n_steps, is_last, state_text_hash, candidates[{id, text, kind, executed, outcome, teacher_pref}], targets{done, value, pick}, label_source, license`. The state holds only what existed before step t (A4 leak rules); never `resolved`, final patch or eval logs. A branch that was not executed is stored with `executed=false` and `outcome=null`. Teacher preference (the frontier's action) is stored separately from outcome.

### 2.2 `done` (stop versus continue): outcome pool only
- **Source:** trajectories with a real test outcome and native negatives: nebius SWE-rebench-openhands (measured above), and on approval SWE-smith, nanoswe, JetBrains (each has a resolved/verified flag).
- **Rows:** the final step of `exit_status == submit` trajectories. The agent made a real stop decision there. Label `done = resolved` (tests on the final patch). Measured balance: 31,020 TRUE / 29,719 FALSE, so the natural split is about 51/49 and needs no re-weighting. An unresolved finish is a real premature or wrong stop, not a fabricated negative.
- **Excluded from `done` finals:** max-iteration, stuck-in-loop, timeout and error exits (6,003 + 252 + ~80 trajectories). No stop decision was made, so a stop label would be invented. They stay available for `value`.
- **Mid-trajectory steps:** `done = FALSE` only as a **weak, position-derived** label, and only when a later step edits files (so the working patch at t is not the final one). Weight low and a separate `label_source=position`; never used for any reported metric. Reason: no tests were run on intermediate patches, so "not done yet" is not an outcome; the headline metric uses final steps only (same as CONDUCTOR_FINETUNE_PLAN.md section 5).
- **Accepted-only sets are excluded from `done`** (Fable, Sol, ARC wins, Dōjigiri): every final is TRUE, so a model could learn "source style => done". Rule kept from DATASET_SOURCES.md H.
- **Counts that survive:** nebius `done` finals = 60,739 trajectories (measured upper bound, before any length or dedup filter). Rows actually captured will be a sample sized from the measured capture cost, not from this number.

### 2.3 `value` (will this eventually succeed)
Every step of a trajectory gets that trajectory's `resolved` (all exit statuses are usable here). It is the weakest supervision (outcome copied backwards), so it is a secondary head output with lower weight and judged only on held-out repos. Dense signals (a test flipping fail to pass inside `last_observation`) can replace it later; not built now.

### 2.4 `pick` / next move: frontier traces (accepted-only), positive-unlabelled
- **What the label means:** "a verified-successful frontier agent chose this action at this state" = teacher preference, not outcome. It trains the head to prefer frontier-like actions among candidates; it never asserts the other candidates are wrong.
- **Candidates:** (a) the frontier's real action (`executed=true`, `teacher_pref=1`); (b) Qwen's own sampled proposals at the same state (4 to 8, `executed=false`, `outcome=null`, `teacher_pref=unknown`); (c) NONE. Generating (b) needs Qwen inference per row, which is why the number of `pick` rows is bounded by compute, not by the 12,490 available (rows needed: a sample; cost unmeasured).
- **Rejected shortcut:** using actions from other steps of the same trajectory as distractors. They are trivially distinguishable from context (wrong file, wrong stage), so the head would learn context-matching instead of decision quality.
- **Match rule:** if a Qwen proposal is equivalent to the frontier action (same tool and normalised arguments), it is marked as a positive too, so equivalent actions do not become false negatives. The rule is fixed before any result is seen and validated by reading 50 pairs per source; its measured false-match rate is reported.
- **Loss:** softmax over candidates with mass on all matched-positive candidates; unmatched candidates are unlabelled (no per-candidate negative target). Report `pick` only as agreement with the frontier on held-out trajectories, never as a success rate.
- **Source attestation:** `model_attested` is False in the sampled rows, so "Fable" is the uploader's claim. Treat the set as "claimed frontier traces" in every report; do not mix it with the outcome pool in one metric.

### 2.5 ARC-AGI-3 (Opus game traces): out of training, optional OOD probe
It is a puzzle game, not coding; mixing it in would teach ARC cues to a head meant for coding. Its labels are strong (replay-verified outcomes, native negatives: 3 lost games and 8 unfinished levels, claimed) but the state is a grid, so it needs a text rendering that the coding head will never see in use. **Decision:** not in TRAIN. If access is granted it serves as an out-of-distribution check of calibration and abstain behaviour (the runbook's OOD delta), once, after a head exists. It needs a manual access request (user) and its counts must be measured from `events.jsonl` before any use.

### 2.6 Dōjigiri and Glint
Dōjigiri: rewards are per task (rubric/pytest blend), not per step, and the action count is unpublished: no row can be given a real step label. Not used. Glint: unreadable, 60 sessions claimed; revisit only if access is given and its sessions are accepted-only (then `pick` at best).

### 2.7 Overlap with coding-decision-cases (measured, `results/raw/overlap-nebius-vs-cases-v2-20261004.json`)
Coding_Decision_Agent's head layers saw `nebius/SWE-agent-trajectories` resolved flags. Measured against our nebius rows: 618 of 1,823 repos (33.9%) cover 31,880 rows (47.5%); 677 of 6,306 instances (10.7%) cover 7,559 rows (11.3%). The scan behind the cases data was capped, so non-overlap is only against the part it saw.
- **Test sets are drawn only from the 1,205 nebius repos not in the cases data** (66.1% of repos), plus any non-nebius source. TRAIN and validation may include overlapping repos.
- Any "pretrained head versus random head" comparison is judged on those test repos only; a gain measured elsewhere would be contaminated.
- The overlap file stays; its v1 sibling is marked superseded.

### 2.8 Splits, calibration, leakage
- Split by **repo** (a trajectory-per-instance count of about 10.6 means instance-level splits leak): `sha256(repo) % 100 < 20` is test, minus any repo in the cases overlap set. Validation is carved from TRAIN by repo. A **new** calibration slice (about 10% of train repos) is defined; the old CAL role and LOCKED are not reused or read.
- Dedup by the sha256 of the rendered state text; one source never contributes a `done` label unless it has native negatives.
- Shortcut checks run before any training: repo-disjoint split, state-blind baseline (task text only), shuffled-state control, and a source-only classifier that must be near chance on `done`.
- Hard rules (`policy/hard_rules.py`) and real tests override the head at inference; nothing here changes that.

### 2.9 Abstention and low-confidence rejection
The head must learn WHEN NOT TO DECIDE, not just which option to pick. This is critical for the wrapper's `abstain_threshold`. 

**Mechanism:** every decision includes a NONE/"not sure" option. The head learns a probability distribution over candidates + NONE. When the head's top-1 probability is below a calibrated threshold, or when the max gap between top two options is below margin, or when the head places substantial mass on NONE (>0.3), the wrapper escalates to the user or tries a rethink round (up to 3 rounds per CLAUDE.md).

**For Fable data:** (a) the frontier's real action with `teacher_pref=1`; (b) Qwen proposals with `teacher_pref=unknown`, unlabelled; (c) NONE as a dummy option with `teacher_pref=unknown`. The loss is softmax over all three groups, with gradient only on the frontier positive(s). The head learns when Qwen's proposals are bad (low scores) or ambiguous (put mass on NONE) and when to abstain.

**Labels:** abstention is not a label; it is an OUTPUT. The head scores each option and learns that low confidence or high NONE probability = abstain. The calibration slice fits the threshold per `(top1_prob, margin, none_prob)` to achieve a target false-approval rate (hard_rules gate § 2.8).

### 2.10 Row building: the concrete recipe
1. **Load Fable shards** (255 parquet files, 12,490 rows). Skip any 0-byte file. Each row has `messages` (cumulative), `target_message_index`, `assistant_step` (text), `task`.
2. **For each row:**
   - **State:** render the messages up to `target_message_index - 1` as a conversation history string. Hash the state to detect dups later.
   - **Frontier action:** the `assistant_step` at the target index. Parse it as a JSON action or extract text summary if not JSON.
   - **Candidates (a):** [frontier action]. Mark `executed=true, teacher_pref=1, outcome=null`.
   - **Candidates (b):** sample 4-8 Qwen proposals at this state (run Qwen on state + frontier prompt once per unique state, batch across multiple rows). Store as `executed=false, teacher_pref=unknown, outcome=null`.
   - **Candidates (c):** add NONE="not sure / low confidence, escalate" as `executed=false, teacher_pref=unknown, outcome=null`.
   - **Row output:** `{state_hash, state_text, frontier_action, candidates: [a,b,c], source: "fable5", trajectory_id, ...}`.
3. **Qwen sampling cost:** run Qwen once per unique state; reuse proposals across rows with identical state. Batch to fit 6 GB. Cost is measured, not claimed.
4. **Dedup:** remove rows with identical state_hash + frontier_action (same decision repeated in different trajectories).
5. **Split:** by repo (not available for Fable; split by first 3 chars of task hash instead), 80% train / 10% val / 10% test. Calibration is a separate 10% of train repos.
6. **Capture Qwen states:** for every row, capture hidden states at 3 depths [18, 24, 30] over [state_text + frontier_action]. Use the frozen Qwen3-4B-Thinking-2507 on the same device class as final TRAIN/CAL/TEST (determined by the user's compute answer).
