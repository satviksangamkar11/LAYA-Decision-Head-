# P3 report: offline, specification-grounded runtime checks (2026-10-20)

Development evidence only (grader cases public in Git). Branch `v1.5-p3-verification`. No GPU, no GLM, no new candidates, no controller change.
Order kept: specs written -> decisions computed and frozen (commit `e6ff22a0`, hashes in `MANIFEST.json`, grader not accessed) -> scored against the existing offline grades.

## What was built
- `tools/p3_specs_v1.py`: one spec per task for the 28 tasks that had any public-passing candidate, written from the TASK TEXT and PUBLIC EXAMPLES ONLY. Each spec has
  `valid(input)` (True / False / None = uncertain), edge inputs the text explicitly permits, and output properties the text states (or that follow by elementary maths, e.g. edit distance
  lies between |len(a)-len(b)| and max(len)). Self-check: every property holds on every public example and every public input is valid (28/28 tasks, 0 problems).
- `tools/el_p3_offline_checks.py`: runs every public-passing stored candidate on the edge inputs + `l2.derive_inputs()`, on the reference engine (WSL bubblewrap; WSLC is down).
  HARD failure = crash on a VALID input, or a stated property violated on a VALID input. Everything else (invalid or uncertain inputs, timeouts, unparsable output) is uncertainty.
  Candidate disagreement on valid inputs is recorded in SHADOW mode only. The P3 answer = the original answer if it has no hard failure, else the next public-passing candidate without one, else BLOCKED.
- `tools/el_p3_score.py`: the separate scoring step.

What changed, per check:
- `literal_pattern_equality` (P1-21: a pattern without wildcards must match only the identical text): rejected the wrong answer, and the next public-passing candidate is grader-correct. **The one P1 selection miss is fixed.**
- `crash_on_valid_input` (P1-28: grid `[[]]`, which the text names explicitly): wrong answer -> BLOCKED.
- `int_range` (P1-31 edit-distance bounds): 4 wrong answers -> BLOCKED (P2 local and Kaggle, failure-aware and counterexample-guided arms).
- `minus1_iff_absent` (P1-25): caught one wrong non-selected candidate; the answer was already correct.
- Shadow disagreement: 2 pools flagged; 1 had a wrong answer (P1-21), 1 a correct one (P1-25). Not reliable as a downgrade signal: stays diagnostic.

## Not caught, and why
11 false SUPPORTED answers remain. They pass every stated property on every valid input tried; catching them needs either a reference oracle or an expected value, which P3 deliberately did not use.
**Known checker limitation (found after scoring, NOT re-scored):** J1-31's wrong answer crashes on the 40-digit input the spec permits, but the legacy Java runner aborts the whole run at the
first exception, so the checker could not attribute the crash to an input and recorded it as uncertainty. A v2 rule (with `term == crash`, the crash belongs to the first input without a result,
because the runner is sequential) is a candidate for integration; it is NOT counted here, because changing a rule after seeing the grades would be tuning against the grader.

## Recommendation for P4 (integration)
1. Integrate as HARD checks: valid-input crash checks and stated-property checks, with input-domain validation, skip-on-uncertainty, and the separate hard / uncertain / infrastructure outcomes. 0 incorrect downgrades on 68 candidates (development evidence; not proof of safety).
2. Keep candidate disagreement as an uncertainty signal only.
3. Budget: about 0.4 s and one sandbox run per public-passing candidate on the reference engine.
4. **Open question for integration:** these specs were written by hand, per task, from the task text. For the live system (any task, any model) the spec must come from somewhere:
   the task author, or properties proposed by a model and admitted only if they hold on all public examples (the same self-check used here). That source is the main design decision for P4.
5. Then P5: one fresh end-to-end comparison of V1 against V1.5 on fresh tasks at identical budgets, before any freeze.

## Limits
28 tasks, 68 candidates, 17 wrong answers: small. Specs were written by one author (me) without grader access, but with the P1/P2 reports already known (no case content).
Reference engine only (WSLC unavailable); Java covered only through J1-17, J1-20, J1-31.
