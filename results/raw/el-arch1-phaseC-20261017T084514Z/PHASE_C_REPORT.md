## C3 LAYA monotonicity gate: DONE (LOGIC-ONLY)
- NEW `controller/monotonicity.py`: `monotonicity_gate(pools)` with pools `{id, scores, passed}` (trusted outcomes). Statistic: pooled concordance (AUC) between score and passing over (passing, failing) candidate pairs, bootstrap CI over pools; plus pass rate by rank position non-increasing within a tolerance on positions reached by enough pools. Returns SUPPORTED / NOT_SUPPORTED / INSUFFICIENT_DATA; `laya_ordering_enabled` is True only for SUPPORTED. `verification_order(gate, items)` always sorts trusted passes first (I2), then uses the LAYA score only when SUPPORTED and enabled, otherwise cheapest-check-first. Parameters in `configs/el_arch1_gates_v1.toml`.
- Tests: 3 examples -> INSUFFICIENT_DATA with ordering disabled; synthetic 200 pools: monotone -> SUPPORTED, anti-monotone and flat -> NOT_SUPPORTED, deterministic for a seed, 20 pools -> INSUFFICIENT; LAYA never overrides trusted evidence under any gate state (including a SUPPORTED status without the enabled flag), and the per-action path agrees (`check_i2`).
- The gate is also run per scorer inside the comparison report as a diagnostic (stage 1 data cannot enable anything: ordering stays a stage-4 decision).
