## Per-dataset notes

**chrissiecsj/ToolPreference.** Card says it is built from ToolBench trees: each branching node on a successful path gives a preferred step (on the path) and a dispreferred sibling. The sample confirmed exactly two outputs per row. The card gives the row counts; the endpoint has no converted rows, so counts are not verified. The licence sentence is in the card body; the API has no licence tag.

**samatv256/jev-decisions-v1.** The Choice target is the action the source trajectory took (imitation label). The card says Choice must not train on failed or unresolved trajectory actions. Value and completion labels are separate and must not be mixed in. The clean-50k subset: "contains no Open-SWE records" (card). Default config is about 22 GB, so use general-clean-50k for a first pass.

**MaziyarPanahi/AgentToolDecisions-180K.** The 6 task families are very different. The sample only covered tool_or_text_action (2 abstract options: "text_response" and "tool_call"). Choice labels are programmatic and automated. The card describes the request format as Jev-style. The card says no Jev output is included. It also states that a model called ModernJEV-Decide-Preview was trained on this dataset.

**nvidia/When2Call.** The mcq and llm_judge splits are the benchmark. Card: llm_judge is a subset of mcq. Do not train on them. The 24-row MCQ sample has correct_answer = cannot_answer in every row; this is a biased sample and is not a distribution estimate.

**tasksource/tasksource-jev-typed-decisions.** Mostly NLP tasks, not agent actions. Soft targets need a rule for "positive" (e.g., argmax, only when one-hot). The card's filter example uses license_use = "commercial".

**skjortan/code-jev.** Binary yes/no facts per function. Choice rows are rare in the sample. Labels are parser-based (exact by construction) or teacher-model labels (descriptors).

**fastino/fast-decisions.** Each row's labels list is the full candidate set. The card says gold labels for the test split are held out; do not report on the dev files as a benchmark (card says so).

**inclusionAI/AReaL-tau2-data.** The SFT rows have one gold answer per turn. There are no alternatives. Turning them into a pool would need generated alternatives, which is not in scope here.

**nvidia/Open-SWE-Traces.** One trajectory per instance, with a trajectory-level resolved flag. The per-step alternatives are not in the data.

## Convertible to (context, options, positive) without a language model?

- **samatv256/jev-decisions-v1 (general-clean-50k and default Choice rows): yes.** The state, the candidate list and the recorded target are all present. Options are 13 to 100, not 3 to 5, so a subsample must keep the target and state the sampling rule. The positive is an imitation label, not a verified-better action.
- **chrissiecsj/ToolPreference: partly.** Context, two ranked alternatives and a preference are all present. Only 2 options, so it does not meet the 3 to 5 target. It fits a pairwise (DPO-style) use.
- **MaziyarPanahi/AgentToolDecisions-180K: partly.** Choice rows with gold_label fit. Options for tool_or_text_action are abstract categories, not concrete actions. noul rows (score 0 to 1) have no alternatives. Other families (tool_selection, argument completeness) were not sampled.
- **nvidia/When2Call: partly.** train_pref gives 2 alternatives. mcq gives 4 answer types with correct_answer, but it is the eval split. train_sft has no alternatives.
- **tasksource-jev-typed-decisions: partly.** Choice rows have 2 to 3 options with a target distribution. Not agent decisions. Needs a positive rule for soft targets and a license filter.
- **fastino/fast-decisions: partly.** The mechanical shape fits (document + full label list + gold). These are classification labels, not actions, so distractors would be label names rather than real alternatives. Dev split only.
- **skjortan/code-jev: no.** Binary per-function yes/no; choice rows are rare.
- **inclusionAI/AReaL-tau2-data: no.** One gold answer per turn.
- **nvidia/Open-SWE-Traces: no.** Trajectory-level outcome only.
- **Salesforce/xlam-function-calling-60k: could not be checked.** Gated, card not readable without login. Accepting access terms needs the user's yes.

## Overlap and lineage risks

1. **Jev naming (not a stated Open-Jev source).** Jev appears in the name or tooling of samatv256/jev-decisions-v1, MaziyarPanahi (request_json as a "Jev API request", "Race Jev"), and tasksource (tags, docs/jev). skjortan/code-jev names openjev as the backbone of the head its data was built for. None of the cards says Open-Jev outputs or Open-Jev-derived data are a source. Whether that holds at the file level (sources.yaml, BUILD.md, SOURCE_LICENSES.md, sources of "jev" builds) is not verified. Under the current rule, code-jev and tasksource need a closer check before use.
2. **Downstream Jev models trained on jev-decisions-v1.** The card says the author's mini-Jev interim checkpoint uses supervision derived in part from it. A mini-Jev teacher would not be independent of this dataset.
3. **Shared upstream: Nemotron-SFT-Agentic-v2.** Both MaziyarPanahi and samatv256 derive from it. Row overlap was not checked, but the card-level overlap is real.
4. **When2Call duplicated.** It is a separate entry here, and MaziyarPanahi contains 26,296 When2Call-derived rows. Using both double-counts.
5. **Open-SWE-Traces duplicated.** samatv256 includes Open-SWE-Traces v1.0 (openhands, sweagent), and the standalone dataset is listed here.
6. **Eval splits.** When2Call mcq/llm_judge, tasksource's Decision Index (card: alignment with private eval rows unverified) and tau2-bench (AReaL) are evaluation sources; do not mix them into training.
7. **Open-SWE-Traces configs.** v1.0, v1.1 and v1.2 may overlap; the 521,712 total is a sum of per-config counts.
8. **Benchmark mentions only.** fast-decisions cites JevK5, SemIf and Laya Router as baselines, not sources.
