Scope: score labelled coding-agent steps with the UNCHANGED `models/coding-decision-agent` through its OWN ModernBERT-large encoder + head, then fine-tune the head only (encoder frozen) on a Kaggle T4. Nothing was run, trained or downloaded; files and safetensors headers were read. Paths are relative to `D:/local model`. "est." = estimate from code and parameter counts, unmeasured.

- Tensor groups (safetensors header read): encoder.layers 343.2M + embeddings 51.6M = 394.8M (the "395M"); head.layers (2 x TransformerEncoderLayer) 25.19M; scorer 1.05M; act_head 0.26M; type_emb 3,072; `temperature` buffer [1,1,1] (unused at inference). Head side total = 26.5M.
- Encoder cfg: ModernBERT-large, 28 layers, d=1024, 16 heads, intermediate 2624, local attention window 128 with a full-attention layer every 3rd, max_position 8192, saved with transformers 5.17.0 (rope_parameters form; `laya/common.py:392-412 _apply_rope_config` maps it for 4.x). Dropouts all 0.0.

No `temperature_by_options` (dropped on purpose, README).

### Rendering a state + question into tokens
`laya/common.py:135-230 build_sequence` (layout in its docstring):
`[CLS] "<type> question: <instructions>" [SEP] [MASK] opt0 [MASK] opt1 ... [SEP] <state> [SEP]`.
- State: `serialize_state` (:74) = the string, or `json.dumps(state, ensure_ascii=False)` for a dict (insertion order kept, so `family` comes first). Any `[MASK]` in the state text is replaced by a space.
- Options: `render_options` (:106). choice: `"key: description"` (just `key` if description empty); score: `"level i: <criterion i>"`; noul: `"false: ..."/"true: ..."`. Each option is capped at 48 tokens (+1 [MASK]).
- Budgets: `head_max_len` (320) caps question text + option block: if options leave <16 tokens, each option is cut to max(4,(320-16)//n) and the question text to max(8, remaining). The state gets whatever is left of `max_len` (2048) minus the closing [SEP]. So the state budget = 2048 - actual head length (about 1,650-1,900 tokens for 2-8 option questions, est.), not a fixed 1,728. Dict/str states are cut on the RIGHT (`ids[:room]`, :195-196); list states are cut on the LEFT (agent.py:871-874). Truncation stats come from `return_truncation_stats=True`.
- Marker positions = index of each option's [MASK]; `Agent._encode_state` (agent.py:859-907) raises if a marker was pushed past max_len.
- Question dict form (`agent.py:836-857 _to_internal`): `{"type": choice|score|noul, "instructions": str, "criteria": dict (choice) | list (score)}`. The wording is part of the model input, so it must match training text exactly.

### Logits
`common.py:318-389 DecisionModel.forward`: encoder `last_hidden_state` -> `+ type_emb(qtype)` (broadcast to all positions) -> 2 pre-norm transformer layers (d=1024, nhead=16, ff 4096, dropout 0.1, SDPA with key padding mask; `_DynamicMultiheadAttention` :249) -> gather hidden state at each [MASK] marker -> `scorer` (LayerNorm, Linear, GELU, Linear->1) -> one logit per option (padded options get -1e4). `act_head` (CLS state + 4 summary stats of the softmax) returns a 2-way act/escalate logit; no loss in the RLCD trainers uses it (the Kaggle notebook only adds `0.0 * act.sum()` to keep DDP happy), so it stays at its pretrained values.
- Decoding `agent.py:1020-1089 _decode_answers`: `z = logits / T`, softmax, with `T = temperature[qtype]` (cfg list, clamped to [0.5, 5.0], `common.py:552-564`) or a `temperature_by_options` bucket if present. So temperature is applied ONLY at decode time, outside the model (agent.py:1030-1036); the safetensors `temperature` buffer is not read. choice -> argmax key + probabilities; score -> expected level + per-level probabilities; `answer_confidence = max(p)`.
- Device/precision: `agent.py:552-555` - on CUDA capability < 8 (T4 = 7.5) autocast is float16 (not the checkpoint's bf16); capability >= 8 uses `amp_dtype` (bf16) unless `LAYA_CUDA_AMP` is set. `laya.load(path, device="cuda", expected_sha256={...})` verifies the weights file first.

## 3. Training code and head-only fine-tuning
Entry points:
- `external/coding-decision-agent/train/train_rlcd.py` (360 lines): the checkpoint author's trainer; single GPU or torchrun; profiles in `configs/train.yaml` (a100_80gb: micro 16, accum 4, bf16, no checkpointing; gpu_24gb: micro 4, accum 16, fp16, checkpointing, max_len 1024, head_max_len 256, LoRA r32 on Wqkv/Wo/Wi; smoke); rolling `checkpoint_latest/` with resume; calibration slice held out first (10%, <=400 per family); `train/calibrate.py` LBFGS fit of one temperature per qtype. Code licence MIT.
- `laya-audit/external-laya/research/scripts/finetune_single_device.py` (353 lines) and `notebooks/laya_finetune_typed_decisions_2xT4_kaggle.ipynb` (DDP script embedded); docs `docs/finetune.md`, `docs/finetune_browser_agent.md` (full 421M fine-tune on one 16 GB GPU, no gradient checkpointing, 4 epochs ~2 h). Apache-2.0.

What is trained: the whole `DecisionModel` (encoder lr 2.5e-5, everything else 1e-4, AdamW wd 0.01, warmup 3%, cosine to 1e-6, grad clip 1.0); LoRA on the encoder is optional (`maybe_lora`, merged back on save).

Loss (train_rlcd.py:290-306; same as notebook): soft CE `-(target * log_softmax(logits)).sum(-1).mean()` (weight 1.0) + a GRPO-style term: sample G=4 zero-mean Gaussian logit perturbations (sigma 0.4 -> 0.1 across epochs), reward = `common.py:450-476 proper_reward` (log score + 0.75 spherical, + ranked-probability for score questions), advantage normalised, loss `-(adv * logp)`. It needs a full soft target per question.

Data format for training (`data/preprocess.py build_items`, `finetune_single_device.py` docstring): one JSONL case = `{"state": dict|str, "questions": {qid: {type, instructions, criteria}}, "gold": {qid: {"probabilities": {key: p}, "label": key}}}`. Each (case, question) becomes an item `{ids, markers, qtype, target(list, normalised), label, family, qid, case_id, source}` saved with torch.save; items whose marker count != option count are dropped. Repo-style rows add `case_id, family, source, group, needs_teacher` and `state["family"]` (validated by `configs/schema.py:validate_case`). Gold probabilities must sum to 1 and cover exactly the option keys (score keys are "0","1",...).
Defaults: max_len 2048 / head_max_len 320 (checkpoint profile) vs 1024/256 (T4 notebook profile); micro-batch 8 (notebook), accum 4, epochs 3-4.

### Head-only mode (minimal change)
`DecisionModel.forward(..., detach_encoder=False)` (common.py:353-357) already detaches `h` after the encoder. But the encoder still runs with autograd on if its parameters require grad (graph built, then dropped), so peak memory is not saved. Minimal change, in a copy of `train_rlcd.py` (do not edit the repo copies):
1. After loading weights: `for p in model.encoder.parameters(): p.requires_grad_(False)`; call the encoder under `torch.no_grad()` (small subclass/wrapper) and keep `detach_encoder=True`.
2. `train_rlcd.py:240-245` already builds optimizer groups with `p.requires_grad` filters, so the encoder drops out of the optimizer. Do not enable encoder gradient checkpointing; `head_checkpointing` is optional.
3. Encoder dropout is 0.0 in `encoder/config.json`, so train and eval mode give the same encoder output; head dropout 0.1 stays active in train mode. Put the encoder in `.eval()` anyway.
4. Save with `laya_state_dict` (train_rlcd.py:108, restricted to template keys); check encoder tensors are bit-identical before/after (the project did this style of check in `tools/laya_headonly_v1.py`).
5. `act_head`: no loss touches it; leave it frozen (exclude it from the optimizer so weight decay does not drift it).
After head-only training, refit the three temperatures on a held-out slice (`train/calibrate.py fit_temperatures`) and write `rl_agent_config.json` with `write_config` (it drops `temperature_by_options`). The shipped [1.116, 1.092, 1.2] belong to the old head.

### Memory / time (est., unmeasured; T4 = ~15 GB usable, fp16, no bf16 hardware)
- Weights: 421M x 2 B = 0.84 GB fp16; fp32 master 1.69 GB.
- (i) Frozen encoder, head-only: encoder fp16 inference 0.8 GB + fp32 head/scorer 0.1 GB + AdamW on 26.5M params ~0.3 GB; head activations at L=2048 ~0.2 GB per sequence (SDPA, no L x L matrix stored) -> micro-batch 8-16 at 2048 tokens fits in roughly 4-6 GB. Measured reference: 252 s for 3,588 `agent.predict` calls (batch 1, ~70 ms per item including tokenisation, cuda, fp16).
- Caching encoder outputs: exact (encoder dropout 0), but the head attends over ALL positions, so full `last_hidden_state` per (state, question) item must be stored: ~2 KB per token fp16 (1.6-4 MB per item; 12-20 GB per 5-8k items at ~1.2k tokens) - too big for Kaggle /working. Recomputing the frozen encoder each epoch costs about items x 70-100 ms (5,000 items ~6-8 min/epoch, est.), so caching is not worth it below ~50k items.
- (ii) Full fine-tune: fp32 weights 1.69 + grads 1.69 + Adam 3.4 = 6.7 GB before activations. Activations without checkpointing ~0.9 MB/token (28 layers) -> ~1.9 GB per 2048-token sequence, so micro-batch 4 at 2048 would not fit (>14 GB). With gradient checkpointing (as in the notebook / gpu_24gb profile, max_len 1024, micro 8) activations drop to ~0.3 GB per sequence -> ~9-10 GB total, fits. Cost ~4x forward (~0.3 s/sequence at 1k tokens, est.). The author's 2xT4 notebook ran ~30k questions x 4 epochs in ~4-5 h (docs/finetune.md). fp16 + GradScaler is required on T4 (train_rlcd uses the scaler when dtype=fp16); the shipped checkpoint was trained in bf16, so first confirm fp16 forward parity (the T4 native run only checked softmax(logits) vs reported probabilities, 3,588/3,588).
- LoRA on the encoder (`--lora`): small optimizer state, but activations still needed (keep checkpointing).

## 6. Plan sketch (design suggestions, not decisions)
1. Scoring the unchanged checkpoint: reuse the `align_capture_t4.py` teacher path; build the state with `data/compaction.agent_trace_state(...)` (or `tool_call_state` / `code_review_state`) and ask existing qids via `questions_for(...)` so wording is exact. Map step-quality labels onto an existing question where semantics fit (`agent_trace.action` / `outcome`, `tool_call.call_verdict`, `code_review.likely_correct` / `merge_action`) before inventing new wording. A new qid/wording is architecturally possible (options are read from text) but has no pretrained calibration and risks the label-following failure the README notes for noul.
2. Always report the zero-shot (unchanged) score on the same held-out items next to the fine-tuned one, plus options-only / no-context controls and the linear-probe baseline (CLAUDE.md rule).
3. Head-only training on Kaggle T4: fp16 autocast + GradScaler, encoder frozen and no-grad, max_len 2048 / head_max_len 320 (checkpoint values) to stay in-distribution, soft targets from the label source, held-out temperature fit, bit-identity check of the 395M encoder tensors.
4. Later encoder training: gradient checkpointing + micro-batch 4-8 at max_len 1024, or LoRA via `train_rlcd.py --lora`; needs a new GO under the "no encoder trained" rule (CLAUDE.md, 2026-10-12).
5. Quick checks before building: (a) dataset-row vs schema.py wording for agent_trace; (b) fp16-on-T4 vs bf16 logit drift on the same items; (c) real token lengths of the labelled steps (state budget ~1,650-1,900 tokens; right-truncation drops the END of a dict state, so put the newest step early, or use a list state which truncates from the left, if recent steps matter).
