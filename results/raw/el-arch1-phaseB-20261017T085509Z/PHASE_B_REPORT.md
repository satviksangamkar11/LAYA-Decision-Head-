## B4 LAYA hand-off - DONE (documentation + hardening; LayaScorer / VerifiedSavedScoreBackend unchanged)
Exact hand-off for the Kaggle kernel (unchanged contract, now enforced and tested end to end with a real `VerifiedSavedScoreBackend`):
1. The kernel captures frozen-Qwen states from the **exact** `context_text` the controller rendered (`AgenticRun.context_text()` -> `render(messages)`) and the **exact option strings** the controller will use (`GEN.render_call` text), with the training recipe on the Kaggle T4 (`laya_runtime.make_provenance`), and returns per pool `{status:"ok", origin:"live_capture_same_process", provenance, context_sha256, options, option_sha256, raw_output_sha256, features_sha256, scores:{laya:{score:[...]},probe,random_head}}`.
2. A second kernel run in `replay` mode re-captures the same saved proposals; `VerifiedSavedScoreBackend.add(live, verify, live_run=, verify_run=, verify_mode="replay")` admits the pool only if both agree (hashes + scores).

New in this phase: a wrong number of scores, NaN or inf, a `ProvenanceError` for an unverified pool, or any scorer exception is journaled as `scorer_unavailable` with the reason (before, a wrong length crashed the step in `decide_next_action`). Test: `t_b4_*` (LOGIC-ONLY: no real LAYA numbers).
