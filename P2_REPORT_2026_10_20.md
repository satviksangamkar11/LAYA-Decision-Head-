## Reading (descriptive)
1. **Generation remains the limit:** on 9 of 13 tasks no strategy found a correct program within 6,000 tokens, in either run.
2. **Failure-aware resampling was the weakest arm in both runs:** 0 correct answers, 2-3 false SUPPORTED, and the most prompt tokens. As built it gave only failure classes without
   exception messages (a design weakness noted during the run, not changed mid-run).
3. **Fresh and counterexample-guided were close:** each got 2-3 correct answers across the two runs; no consistent winner on 13 tasks. Counterexample-guided used the fewest model calls.
4. **Public examples remain a weak oracle:** 7 false SUPPORTED answers across the arms (local Python 5, Kaggle 5 incl. Java) — every one passed all public examples but fails the grader. This supports P3 (runtime oracle strengthening) more than any retry strategy.
5. Local and Kaggle differ in detail (different GPU sampling and sandbox), but agree on 1-4.

## Findings during the run
1. **Trusted verifier bug (fixed, v3, commit b09a2592):** the host Java `Runner` was compiled once against a stub `Object solve(Map)`; a correct candidate declaring a specific
   return type (e.g. `List<Boolean> solve(Map)`) failed every input with `NoSuchMethodError`. P2 local J1-20: 8 grader-correct candidates rejected. v3 compiles the host `Runner`/`Json`
   against the candidate's compiled `Solution` (no candidate source in that workspace). Re-validation: the 8 J1-20 candidates now pass their public examples on WSLC (8/8), J1-17 parity 4/4,
   phaseF2d 26/26, phaseF3d 16/16 (`results/raw/tv-v3-validation-*`). The Kaggle jail compiles the runner together with the candidate and was not affected. Earlier bank runs used v1/v2 on Java;
   P1's offline grading on the reference engine found no correct candidate that the runtime had rejected, so P1's conclusions stand.
2. **WSLC outage (open):** during the local Java re-run (00:40 UTC) WSLC began failing every call with `WslcListSessionImages ... HRESULT 0x80070057`; the harness failed closed (no verdict
   recorded). A fresh, empty session store gives the same error (the old store file is kept in `models/wslc-store-suspect/`). WSL itself is unchanged (3.0.3.0). Restarting the WSL service
   needs admin rights; a reboot is the likely fix. Local Java P2 therefore has no valid rows; the Kaggle Java rows are the Java result.
3. The first uncorrected local run is kept and marked SUPERSEDED; the crashed Java re-run is kept and marked CRASHED.
