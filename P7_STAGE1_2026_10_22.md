## 1. Power: how many sealed tasks a confirmation needs
Paired task-level outcome, 80% power, two-sided 0.05. `delta` = gain in solved-task fraction, `l` = fraction of tasks the treatment loses.
| delta | l = 0 | l = 0.03 | l = 0.05 | l = 0.10 |
|---|---|---|---|---|
| +5 pts | 150 | 338 | 464 | 778 |
| +10 pts | 71 | 118 | 150 | 228 |
| +15 pts | 45 | 66 | 80 | 115 |
| +20 pts | 32 | 44 | 52 | 71 |
- With sampling noise, a realistic `l` is 0.03–0.05, so detecting +15 points needs **66–80 sealed tasks**, +10 points **118–150**.
- `l` is measured, not assumed: the pilot runs the baseline twice (A/A); half its discordance sets `l` (floor 0.03).
- P6's 72 Codeforces tasks at 11% solved could only ever confirm a very large gain.

- **More samples of the same model is not the lever on Codeforces.** 1,846 samples on the 64 unsolved tasks, 0 strict successes. Upper 95% bound on a
  per-sample success rate: 0.16%; doubling the budget would add **at most ~2.9 tasks** (upper bound; likely fewer). Contract: at most ~1.6 of 4.
- **Duplicates are not wasting the budget** (0 repeated programs), so de-duplication or diversity prompts have nothing to recover.
- **Crashes are not a cheap fix.** 647 distinct B programs crash on the generated tests; **645 crash on the first test, and none of them passes the statement
  examples**, so B's example filter already rejects every one. A crash fix would also need the program's algorithm to be right, and the non-crashing
  programs are almost all wrong (997 wrong answer, 226 timeout). Static flags (ast only): 4 syntax errors, 31 recursive. No stderr was logged, so exception
  types are unknown; capturing them (a Kaggle CPU run) is **not recommended**: no outcome it could show would change the decision.
- Near misses (most generated tests passed before the first failure, unsolved): 2050/B (7), 2062/B, 2033/B, 2030/C, 2029/B (4 each). Small.
